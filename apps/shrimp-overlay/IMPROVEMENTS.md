# 캐릭터 채팅마을 개선점 점검 — v1.4.1

2026-10-05. 현재 소스와 자동 테스트를 기준으로 작성했습니다. 실제 Windows OBS 화면을 관찰한 결과는 아닙니다. 사용자 피드백을 설명하는 코드 원인, 이번 수정, 앞으로 검증하고 개선할 영역을 구분합니다.

## 현재 상태 분석

사용자가 느낀 “채팅이 뜰 때 커졌다 작아졌다”는 느낌을 설명할 수 있는 직접적인 처리가 있었습니다. 말하기 모션은 몸의 가로·세로 배율을 주기적으로 바꾸고 대기 그림과 말하기 그림을 반복해서 섞었습니다. 두 그림은 입뿐 아니라 몸 외곽과 자세도 다르므로, 작은 배율 변화만 제거해도 외형 변화가 남을 수 있습니다. 말풍선 자체는 확대 애니메이션을 사용하지 않고 투명도로 나타납니다. 따라서 말풍선과 캐릭터를 함께 봤을 때 느껴지는 움직임을 각각 구분할 필요가 있습니다.

v1.4.1에서는 일반 말하기에 대기 몸 그림을 고정했습니다. 몸의 배율, 회전과 위아래 움직임을 고정하고, 원본 아틀라스의 입 주변만 별도 영역으로 합성합니다. 13종의 입 위치를 각각 지정했으며 짧은 열림과 쉼을 반복합니다. 음성 분석을 통한 실제 립싱크는 아닙니다. 입 위치와 합성 경계는 실제 브라우저에서 확인할 필요가 있습니다. 인사·점프 등 메시지에 반응하는 별도 동작은 유지되므로, 그런 메시지를 보내면 전체 몸이 움직일 수 있습니다.

전체 프로그램은 채팅 연결과 표현을 분리하고 있어 개선할 기반은 있습니다. 연결 계층은 인증, 재연결, 중복 제거와 OGQ 정규화를 담당하고, 화면 계층은 캐릭터 상태와 말풍선 공간을 관리합니다. 선택한 캐릭터만 로딩하고 캐시 상한을 두며 숨겨진 관리 화면 미리보기를 멈추는 방식은 인원이 많을 때 불필요한 처리를 줄이는 데 도움이 됩니다. 다만 캐시가 있다는 사실만으로 실제 방송에서 충분히 부드럽다고 결론 내릴 수는 없습니다. 그림 합성, 글자 측정, 그림자, OBS 브라우저 소스의 설정과 실제 그래픽 장치의 영향을 함께 측정해야 합니다.

가장 먼저 개선할 기능 문제는 같은 시청자의 연속 채팅입니다. 현재 같은 종류의 메시지로 바뀌면 이미 표시된 말풍선의 크기를 다시 계산하지 않습니다. 짧은 문장에서 긴 문장으로 바뀌었을 때 기존 공간에 맞춰 줄 수가 제한되므로, 표시할 수 있는 분량보다 일찍 내용이 생략될 수 있습니다. 단순히 모든 메시지마다 새 말풍선을 만들면 깜박임과 크기 변화가 늘어납니다. 기존 표시 시간을 유지하면서 내용과 필요한 공간을 함께 갱신하는 방식이 필요합니다.

설정 변경도 별도 문제입니다. 화면 설정을 받으면 기존 말풍선을 모두 대기열로 돌려보냅니다. 이 방식은 크기나 폰트처럼 배치에 영향을 주는 설정에는 필요하지만, 캐릭터 밝기나 성능 설정처럼 말풍선 내용과 관계없는 변경에도 적용됩니다. 사용자는 설정 저장이 화면 전체를 다시 시작하는 것처럼 느낄 수 있습니다. 영향을 받는 부분만 갱신하는 방식으로 바꾸는 것이 자연스럽습니다.

시각적 완성도는 동작 개수보다 전환과 일관성에 달려 있습니다. 캐릭터마다 귀·날개·꼬리·장미 꽃잎 등이 있기 때문에 외곽을 기준으로 그림 크기를 맞추면 몸통의 크기가 같게 유지되지 않을 수 있습니다. 방향별 걷기 그림도 발 위치와 몸 중심이 완전히 같다고 보장할 수 없습니다. 현재 보간이 변화의 속도를 완화하지만 그림 자체의 기준점 차이를 모두 해결하지는 못합니다. 캐릭터별 몸통 기준점과 발 접지선을 갖추고 실제 화면에서 비교하는 작업이 다음 품질 개선의 핵심입니다.

## 이번에 반영한 수정

- 일반 채팅: 몸과 눈의 그림 및 배율 고정, 13종 입 부분만 독립적으로 변화.
- 주아/개구 폰트: 선택한 글자 두께를 무시하던 고정 400 값을 제거.
- 관리 화면 채팅 로그: 글자가 없는 OGQ 메시지에 `[OGQ 이모티콘]` 표시.
- 회귀 테스트 포함 자동 테스트 26개 통과. 실제 브라우저 합성과 OBS FPS는 미검증.

## 다음 개선 아이디어와 우선순위

1. **연속 채팅의 말풍선 갱신 — 높음 / 확인된 문제**
같은 시청자가 짧은 채팅에서 긴 채팅으로 바꾸면 새 내용에 필요한 크기를 측정해야 합니다. 기존 말풍선의 시작 시간은 유지하고 주변 말풍선과 충돌하는지 확인한 뒤 갱신하는 방식이 적합합니다. 공간이 부족하면 최신 메시지를 잠깐 대기시키거나 최대 폭 안에서 줄을 늘릴 수 있습니다. 검증에는 짧은→긴 문장, 긴→짧은 문장, 텍스트→OGQ, OGQ→텍스트, 빠른 연속 입력을 포함해야 합니다. 완료 기준은 이전 크기 때문에 문장이 불필요하게 생략되지 않고 표시 시간과 대기열 상한도 유지되는 것입니다.

2. **설정별 부분 갱신 — 높음 / 확인된 문제**
설정을 저장할 때 변경된 키를 비교해 영향 범위를 나누는 것이 좋습니다. 색상·밝기는 캐시만 갱신하고, 폰트·말풍선 폭·여백은 해당 배치를 다시 측정하며, 캐릭터 종류는 이미지만 교체하도록 구성할 수 있습니다. 연결 주소나 방송 ID는 실제 연결 처리와 장면 초기화를 따로 수행합니다. 이름표 색상 하나를 바꿨다고 이미 표시 중인 채팅까지 다시 등장하지 않게 하는 것이 목표입니다. 빠르게 여러 설정을 바꿀 때 오래된 이미지 로딩이 새 선택을 덮어쓰지 않는지도 함께 확인해야 합니다.

3. **캐릭터별 몸통·발 기준점 — 높음 / 육안 검증 필요**
현재 그림을 잘라낸 외곽 크기에 맞추는 방식은 손을 들거나 꼬리가 넓어진 그림에서 몸통 크기가 달라질 수 있습니다. 각 포즈에 몸 중심, 발 접지선과 얼굴 중심을 저장하면 같은 크기 설정에서도 몸통은 안정적으로 유지됩니다. 새우 더듬이와 다람쥐 꼬리처럼 큰 부속물이 있는 캐릭터를 우선 비교하는 것이 좋습니다. 걷기 네 프레임을 겹쳐 보고 몸통 높이와 발 위치가 얼마나 차이 나는지 확인해야 합니다. 이는 단순한 보간 강도 증가보다 그림 변화의 원인을 직접 줄이는 작업입니다.

4. **입 레이어 위치와 경계 검수 — 높음 / 이번 수정의 남은 검증**
입만 움직이는 방식은 몸 전체를 교체하는 문제를 줄이지만, 원본 그림 두 장의 피부색이나 입 각도가 다르면 작은 경계가 보일 수 있습니다. 새우부터 올챙이까지 13종을 기본 크기, 최소 크기와 최대 크기로 비교하고 밝기 및 색상 변경도 적용해야 합니다. 오리·참새는 부리가 자연스럽게 열리는지, 물개·다람쥐는 코와 수염 쪽이 움직이지 않는지 확인해야 합니다. 문제가 있는 캐릭터는 독립 입 리소스로 교체하는 편이 낫습니다. 현재 위치 데이터가 있다는 사실과 시각적으로 완성됐다는 판단은 구분해야 합니다.

5. **실제 다수 캐릭터 성능 측정 — 높음 / 측정 필요**
동일한 OBS 해상도와 프레임 설정에서 12·24·48명을 각각 표시하고 기본 글자, 긴 이름표와 움직이는 OGQ를 함께 테스트하면 병목을 찾을 수 있습니다. 평균 FPS뿐 아니라 프레임 간격의 상위 구간과 그리기 시간을 기록해야 순간적인 끊김을 파악할 수 있습니다. 관리 화면 미리보기 동시 실행 여부도 비교할 필요가 있습니다. 측정 결과에 따라 그림자 비용, 합성 횟수, 글자 캐시와 화면 지우기 범위를 조정합니다. 실제 측정 전에 특정 PC에서 60fps를 유지한다고 보장해서는 안 됩니다.

6. **동작을 캐릭터 성격별로 배분 — 중간 / 표현 개선**
현재 캐릭터별 이동 프로필은 다르지만 자율 동작 목록은 공통입니다. 참새는 짧은 깡충과 고개 갸웃, 물개는 느긋한 흔들기, 꿀벌은 짧은 떠오름, 티백은 가벼운 까딱처럼 동작 비중을 다르게 줄 수 있습니다. 모든 캐릭터가 동일한 종류를 똑같이 반복하는 느낌을 줄이는 것이 목적입니다. 연속으로 같은 동작이 나오지 않는 규칙과 큰 동작 뒤 짧은 휴식을 함께 넣으면 과도하게 산만해지는 것도 막을 수 있습니다. 새 그림이 필요한 동작과 기존 그림으로 표현할 동작을 구분해 제작해야 합니다.

7. **자동 정지와 말하기 전환의 접지감 — 중간 / 전환 검수**
채팅이 들어오면 현재 속도에서 감속한 다음 말하기로 넘어가지만, 마지막 걷기 그림과 앞을 보는 그림 사이에 형태 차이가 있을 수 있습니다. 완전히 정지하는 순간 짧은 안정 구간을 두고 발 위치와 얼굴 방향을 맞추는 방법을 검토할 수 있습니다. 말풍선은 멈춤이 완료된 뒤 표시하고 사라질 때는 잠깐 입을 닫은 다음 다시 걷는 것이 자연스럽습니다. 반응 속도가 지나치게 늦어지지 않도록 지연 상한을 정해야 합니다. 이미 있는 감속을 없애기보다 정지 뒤의 그림 연결을 정리하는 개선입니다.

8. **말풍선 공간 부족을 설명하는 상태 표시 — 중간 / 운영 편의**
현재는 캐릭터 바로 위에 가까운 한 줄 배치를 우선하므로 사람이 밀집하면 일부 메시지는 대기하고 오래된 메시지는 제외됩니다. 방송 화면을 채팅 로그처럼 가득 채우지 않는 선택은 유지할 수 있지만 관리 화면에는 현재 대기 수와 제외 수를 보여 주는 것이 좋습니다. 인원이 많을 때 말풍선 최대 폭이나 동시 표시 수를 줄이라는 안내도 해당 상황에서만 표시할 수 있습니다. 사용자는 채팅 소켓이 끊긴 것인지 단순히 공간이 부족한 것인지 구분할 수 있어야 합니다. 방송용 화면에는 운영 정보를 넣지 않아도 됩니다.

9. **캐릭터별 색상 원형 보존 — 중간 / 디자인 개선**
시청자별 색상은 구분에 도움이 되지만 전체 그림에 같은 색상 회전을 적용하면 장미·감자튀김·고릴라의 고유한 색이 달라질 수 있습니다. 캐릭터 원래 색상은 유지하고 이름표나 작은 장식 색상으로 시청자를 구분하는 선택지를 추가할 수 있습니다. 밝기 조절도 단순한 밝기 증가 외에 윤곽 대비와 색의 채도를 분리하면 더 섬세하게 맞출 수 있습니다. 먼저 흰 배경과 어두운 실제 방송 화면에서 가독성을 비교하는 것이 좋습니다. 사용자가 좋아한 캐릭터의 기본 분위기를 지키면서 구분 정보를 추가하는 방향입니다.

10. **꾸미기 프리셋과 미저장 상태 — 중간 / 사용성 개선**
설정 항목이 많아진 만큼 ‘밝고 아담하게’, ‘채팅 크게’, ‘인원 많게’ 같은 프리셋을 제공하면 시작이 쉬워집니다. 프리셋을 선택한 뒤 사용자가 바꾼 값은 별도로 유지하고 기본값 복원은 연결 설정을 건드리지 않도록 하는 것이 좋습니다. 저장하지 않은 변경이 있을 때 버튼이나 문구로 상태를 알려 주면 미리보기와 실제 방송이 다른 이유도 이해하기 쉽습니다. 저장 전 임시 미리보기를 도입한다면 방송용 소스에 적용되지 않도록 분리해야 합니다. 이 기능은 설정을 더 늘리는 대신 현재 설정을 사용하기 쉽게 만드는 개선입니다.

11. **OGQ 관리 화면 미리보기와 실패 사유 — 중간 / 운영 편의**
이번에는 빈 로그에 OGQ 표시를 넣었지만 실제 이모티콘 종류까지 보여 주지는 않습니다. 관리 화면에 작은 썸네일과 로딩·대체·실패 상태를 표시하면 동작을 쉽게 점검할 수 있습니다. 움직이는 리소스가 없어서 정적 그림으로 대체된 경우와 외부 이미지 로딩이 실패한 경우를 구분하는 것이 좋습니다. 실패한 항목은 제한된 횟수로 다시 시도하고 캐시 상한을 유지해야 합니다. 이 기능을 넣을 때 이모티콘 원본을 재배포하거나 임의 URL을 허용하는 방식으로 바꾸지 않아도 됩니다.

12. **한글·이모지 줄바꿈 정확도 — 중간 / 경계 사례**
문자 단위로 자르는 현재 줄바꿈은 결합 이모지나 복합 문자의 표시를 깨뜨릴 수 있습니다. 글자 묶음 단위로 순회하고, 마지막 줄의 말줄임표도 같은 단위로 제거하면 안전합니다. 가족 이모지, 피부색이 포함된 이모지, 한글과 영문 혼합 문장, 아주 긴 계정명과 줄바꿈이 많은 메시지를 검증해야 합니다. 폭과 줄 수를 제한하는 현재 정책은 유지하되 실제로 보이는 한 글자를 중간에서 자르지 않는 것이 목표입니다. 채팅 길이가 길어져도 측정과 캐시 메모리의 상한은 함께 지켜야 합니다.
